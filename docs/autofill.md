# 依來源自動選填（DDD-08 切片）

案件內按「自動查詢選填」，查詢後檢查草稿與來源，再按「套用全部有來源的空欄」。套用後回到資料核對，檢查單選框、量測與級距，再人工確認。整理書表 HTML 的選項會顯示 ☑／☐，可列印為 PDF；原始上傳 PDF 不會被改寫。

## 已接線的來源與計算

| 欄位／來源 | 實際行為 | 缺資料時 |
| --- | --- | --- |
| 已保存的文件文字 | 重用 `parse_case`；明確同列的比準地／比較標的已勾選選項由 `marked_choices` 解析，附文件 ID、頁碼及原文；不重跑 OCR | 未勾選、衝突選項、多比較標的及無法唯一識別的文字留待確認 |
| 案件名稱、地址、地段、日期、原文總計 | 只套用解析器讀到且在原文有對應引用的空欄 | 不從區域設施清冊推定案件資料 |
| 政府設施來源 | 依目前基準項目映射既有新北市／教育部來源，重用 `fetch_valuation_factors`，呈現來源網址、抓取時間、狀態及候選 | 學校需學年度；重型資料集與未登錄來源跳過並說明 |
| 道路平均寬度 | 有來源的已開闢道路寬度清單 → `calculate_average_road_width` | 缺量測或來源不計算 |
| 建築密度 | 有來源的已建築面積及區段總面積 → `calculate_building_density` | 無效輸入／單位不同不計算 |
| 明定直線距離的基準 | API 接受同一平面公尺座標系的四個座標值 → `calculate_straight_line_distance`；目前 UI 未提供座標輸入 | 不將經緯度當公尺、不代替步行距離 |
| 等級、修正率、總計 | 重用案件指定版本的 `classify`／`review`；計算引擎有足夠已確認輸入及 expected 結果時才能補值 | 不自動確認輸入、不補零、不自訂公式 |

依使用者決定，本次不新增地址／地號定位服務。設施清冊無法證明特定宗地的距離、所在區段或「有／無」；API 候選保留在查詢預覽供核對，不直接變成案件欄位。資料取得時間也不等於估價日期的歷史適用性。每個基準因素列出缺少的欄位及可用來源；未支援的規則不宣稱已完成。

## 契約、保存與作業方式

- Application 的 `FieldDataSource`／`AutofillDraftStore` ports 位於 `autofill_contracts.py`；infrastructure 提供政府 API、既有 cache 與工作佇列 adapter，由 `bootstrap.py` 注入。domain 不依賴外部 API。
- `POST /api/cases/{id}/autofill/jobs` 回傳 202；`GET /api/cases/{id}/autofill/jobs/{job_id}` 輪詢結果。背景工作一個 worker、最多兩個執行／排隊工作，避免整批 API 等待卡住 HTTP。關閉對話框可在相同案件版本重新開啟查看。
- 預覽不變更案件或 audit。伺服器保存可信草稿 15 分鐘，`POST /api/cases/{id}/autofill/apply` 只接受 revision 與 token。查詢前後和套用時均檢查版本；不接受客戶端提供的 patch 值。
- 只填空欄；0、「無」、既有資料、免比較與特殊備註保持不同語意。套用以一次案件 revision／audit 保存，受影響確認狀態失效。
- `Case.field_sources` 為預設空陣列的新增欄位，保存文件／函式及其輸入依據。正常儲存不接受客戶端偽造來源；欄位或計算依賴改動時清除過期來源。HTML 匯出包含來源表。
- SQLite 表結構不變，舊案件可直接載入。舊版程式的嚴格模型可能拒絕新版案件 JSON；有新版寫入後不可直接切回舊程式，需先規劃保留新資料的相容轉換。部署前停機備份資料；切換失敗且尚無新寫入時才可回復原版。
- 佇列狀態限單程序記憶體，重啟後需重新查詢；目前 AWS 使用一個 uvicorn worker。這不是分散式工作佇列。
